# 필드 결함 지식으로 유사 결함 예방

이전 세대 제품의 필드 경험으로 Knowledge Base를 구축하고, 다음 제품의 요구사항·설계·구현·시험에서 LLM Agent가 이를 활용하도록 하는 한 장 HTML 발표 자료입니다.

이전 제품 데이터는 회색, Knowledge Base는 녹색, 다음 제품 개발은 파란색으로 역할을 구분합니다. 왼쪽은 이전 세대 데이터, LLM Post-mortem, Knowledge Base를 위에서 아래로 연결합니다. 이전 세대의 검증 자료는 테스트 실행 이력과 불량 수정 내역을 명시합니다. Post-mortem은 결함 원인·미검출 요인을 분석해 재사용할 패턴으로 정리하는 역할을 표시합니다. Knowledge Base에서 오른쪽의 다음 제품 요구사항·설계·구현·시험으로 연결선을 나누어 활용 관계를 보여줍니다. 연결선에는 비교·제안을 표시해 지식과 다음 제품 산출물을 비교하고 보완안을 만든다는 역할을 보여줍니다. 표시는 연결선 위에 두어 선과 겹치지 않게 배치합니다.

Knowledge Base는 패턴을 행으로, 발생 원인·미검출 원인·예방 및 검증 항목·적용 조건을 열로 둔 표입니다. 행별로 같은 항목을 채워 지식을 누적하는 모습을 보여줍니다. 표의 내용은 저장 구조를 설명하기 위한 일반화된 패턴 예시이며 실제 고객 결함 데이터는 아닙니다. 오른쪽은 요구사항·설계·구현·시험 카드만 표시합니다. LLM Agent의 역할은 상단 설명에서 밝히며 별도 그룹 테두리와 제목은 제거했습니다. 각 단계에는 기대 효과 제목을 붙이고, 효과를 큰 문구로 두며 산출물 보완안을 함께 표시합니다. 반복되던 활용 지식 목록은 제거했습니다. 제목은 유사 결함 예방이라는 목표를 표현하고, 제목 아래에는 여러 결함·산출물을 연계 분석한 지식으로 다음 제품에서 놓친 조건을 찾는 LLM Agent 구축이라는 방향을 한 문장으로 표시합니다. Knowledge Base는 다섯 열과 두 예시 행만 표시하며, 표 아래의 중복 설명은 제거했습니다. 표의 글자를 키우고 카드 높이를 내용에 맞췄습니다. 입력 자료와 개발 단계에는 자체 SVG 아이콘을 사용합니다. 분석 기법 이름, 정형적인 Post-mortem 단계 설명, 결함 ID 등 상세 추적 정보는 발표 화면에서 제외했습니다.

SSD 맥락은 Power loss·Reset, Command 취소 등 적용 조건에 반영합니다. 실제 제품의 결함 원인이나 구현 방식을 단정하지 않는 저장 구조 예시입니다.

각 행 전체가 하나의 재사용 가능한 패턴 지식입니다. 첫 열은 반복되는 조건·실패 양상을 요약하고, 발생 원인 열은 이를 유발한 내부 처리·설계 요인을 설명합니다. 표에는 중단 후 복구 실패와 반복 취소 시 자원 고갈의 두 예시를 표시합니다. 하단의 세로 말줄임표는 같은 구조로 다른 패턴이 이어짐을 나타냅니다.

Agent는 이 지식과 다음 제품의 산출물을 비교해 요구조건 누락, 놓친 Failure mode, 취약한 코드 경로, 빠진 시험조건을 찾고 보완안을 제안합니다. 구현 단계는 Code review에서 의심 코드와 수정안, Unit test를 제안하는 활동으로 표시합니다. 요구사항·설계·시험의 출력 역시 보완안으로 표현합니다. 시험은 Test spec의 조건·판정 기준 보완안과 Test code의 테스트 추가안을 구분합니다. 검증 범위 확대는 기존 검증에서 빠진 조건·처리·시나리오를 찾아 개발 산출물과 검증 항목에 반영한다는 의미입니다.

## 자료

- `release/presentation.html`: 공유용 단일 HTML 파일. 별도 설치나 외부 네트워크 없이 브라우저에서 열 수 있습니다.
- `docs/index.html`: 같은 자료의 정적 사이트 진입점
- `slides.md`: Slidev 원본
- `release/overview.png`: 전체 그림 미리보기

## 명령

```bash
npm run build           # 정적 HTML과 공유용 단일 HTML 생성
npm run export          # 동일한 HTML 생성
npm run preview         # 브라우저 레이아웃 확인과 미리보기 생성
npm run verify:offline  # 외부 리소스 의존성 및 한 장 구성 확인
npm run dev             # Slidev 편집 서버
npm run build:slidev    # Slidev 번들 생성
```
